# v2026.10.16-4 pre-release tests

Tested on the evening of 2026-10-16, right after it was cut. It is
[v2026.10.16-3](v2026.10.16-3.md) with both kernel tracks updated - a
security release: Linux **7.2.11** (stable, the default) and **6.18.57**
(longterm), proposed by upstream-watch in
[#124](https://github.com/swenske/Janus/pull/124) and
[#123](https://github.com/swenske/Janus/pull/123) and merged together
with the notes in [#129](https://github.com/swenske/Janus/pull/129).
Both fix CVE-2026-99999 (critical, the IPv4 stack); longterm also fixes
nine rated high. Nothing else changed on the nodes. This run repeats the
update steps on the new kernels, measures the release again the same
evening, and adds a machine on the longterm track.
The scenarios: [Lab test scenarios](lab-scenarios.md).

## Verdict

**Ready to promote.**

- **The new kernels behave as the old ones**: the Controller's update,
  the rolling update, failovers, firmware and kexec reboots, rollbacks
  and HAProxy's throughput all match v2026.10.16-3, measured the same
  evening (throughput within 2 %, both ways).
- **kexec on 7.2.11**: `kernel/patches/0001` (the EFI stub's INITRD
  table) still applies, and every kexec reboot came back without an
  oops - in CI under both OVMF builds, on the lab's nodes three times
  chained.
- **The longterm track, end to end**: a machine created through the
  Controller with `kernel: longterm` - the image factory built its image
  in a minute - runs 6.18.57, SELinux enforcing with no denial, CIS
  33/33, its kernel messages sent to the fleet's targets; it rebooted
  through kexec and the firmware.

## Before the merge

`ci.yml` doesn't build kernels, and a branch dispatch of image-build
would push the Controller's `latest`: the merged branch was checked on
a build machine first - both kernels built with `kernel/patches/`
applied, `kernel/check-track.sh` for both tracks (the configuration is
kbuild's own, the list of built files current), `qemu-boot-test`,
`qemu-hardening-test` and `qemu-network-test` on both, the Raspberry
Pi kernel (its configuration and built files) and `qemu-raspi4-boot-test`,
`qemu-selinux-test`, `qemu-kexec-test` and `qemu-kexec-secboot-test` on
7.2.11 - all green ([#129](https://github.com/swenske/Janus/pull/129#issuecomment-6221911454)).

(the Controller's profile on every node). The fourth client machine

the lab changed, so the release's throughput was measured again that
evening, from the same clients, before the update.

and of 2,195 on the anycast address.
