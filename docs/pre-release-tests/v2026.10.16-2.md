# v2026.10.16-2 pre-release tests

Tested on the early afternoon of 2026-10-16, right after it was cut. It is
[v2026.10.16](v2026.10.16.md) plus the fix of what that campaign found
([#121](https://github.com/swenske/Janus/pull/121)): this run checks the
fix on the lab's nodes, and repeats the campaign's steps that a change to
janusd's start could move. The figures to compare with are v2026.10.16's
and v2026.10.15-2's, measured the same morning.
The scenarios: [Lab test scenarios](lab-scenarios.md).

## Verdict

**Ready to promote.**

- **The fix holds on the lab**: on every boot of the updated nodes - the
  update itself, firmware and kexec reboots, a rollback - each node sent
  about **700 kernel messages, all under its own name**; v2026.10.16 sent
  9. One boot on v2026.10.16 in between (a rollback) sent almost none
  again - the defect, and the fix, on the same node. Nothing went out
  under an address any more.
- The machine with the LOGS partition, updated by the Controller in 15 s,
  sent its boot through the partition as before (605 messages).
- Everything else matched v2026.10.16: the Controller's update, the
  rolling update, reboots, rollbacks, throughput, SELinux enforcing with
  no denial, CIS 33/33.
