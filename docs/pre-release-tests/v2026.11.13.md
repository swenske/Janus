# v2026.11.13 pre-release tests

Tested on 2026-11-13, the day it came out, on the lab whose Controller
and nodes ran v2026.11.10 - the newest release
([v2026.11.10's report](v2026.11.10.md)). What the pre-release
changes:

- **the pages open read-only** (#636): a switch in both headers hides
  every action until it's turned to Editing, back to read-only by
  itself after a delay without activity, never in the middle of an
  action;
- **Go 1.27.4** for every Janus binary (#635);
- **Linux 7.3.4** (the default track) and **6.18.63** (longterm);
- **Docker Compose v5.7.1** in the Controller's updater (#633).

The campaign: the release measured first (boot stages, throughput,
health), the Controller's update through its updater and the image
factory, the Read-only switch in the pinned Chromium - 32 pages in both
modes and both themes, a node page opened from the Controller's, the
account's preferences, the delay with Playwright's clock (idle, a
confirmation open, a kernel parameter on trial, an update under way),
a reader and an operator -, then the core: the cluster updated in place
under load, a VRRP and a BGP failover, HAProxy reloads, firmware
reboots and kexec on both kernel tracks, a rollback and back, the
nodes' health, and HAProxy's cost per request with the release and the
pre-release alternated on node 01 by rollbacks. The load and the probes
came from the build box and one CI runner, the release measured from
the same clients the same day.

## Verdict

**What the pre-release changes works on the lab. Every page opens
read-only and shows no action - on the Controller and on a node -
while Validate, the editors' Check, the connectivity test, the capture
and the diagnostic bundle stay; in Editing each page offers exactly the
buttons v2026.11.10 showed. A node page opened from the Controller's
in Editing opens in Editing, the address's `?edit=1` gone at once. The
preferences are kept with the account, the delay puts the page back to
read-only with its toast, and never while a confirmation is open, a
kernel parameter is on trial or an update is followed - the update
went to its end. A reader has no switch; an operator gets their own
actions back in Editing. Go 1.27.4 is in every binary checked, the
updater runs Compose v5.7.1 after `docker compose up -d`, both kernels
boot as fast as before with zero AVC and CIS 33/33. The core campaign
is as before: the cluster updated in place without a lost request (VIP
0 of 3,297, anycast 0 of 3,296), the same failovers, boot times and
cost per request. My opinion: ready to promote** - the findings are
minor and none is new in this release. The decision is yours.

## Findings

1. **Listing `/sbin` through the file API leaves two AVC denials** -
   minor, not new: `janusctl system ls /sbin` (an admin's call)
   shows `init` and `shutdown` as "permission denied" and logs two
   `getattr` denials for janusd (`init_exec_t`, `shutdown_exec_t`),
   which the health check then counts. The SELinux policy and the file
   API are the same in v2026.11.10 and the pre-release; janusd could
   leave those entries out, or the policy allow `getattr` on them.
2. **A test job failed on a busy runner**: the Controller's libvirt test
   expects auto-scaling to add a vCPU under load, and the Controller
   rightly refused with the runner's host short of CPU (12 % steal) -
   six of the build's jobs ran on that runner at once. Run again, it
   passed. A test that depends on the host's spare CPU; not a defect of
   the release.
