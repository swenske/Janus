# v2026.10.16-3 pre-release tests

Tested on the afternoon of 2026-10-16, right after it was cut. It is
[v2026.10.16-2](v2026.10.16-2.md) plus the Log forwarding pages' fixes
([#126](https://github.com/swenske/Janus/pull/126)): the targets folded
with their state, changes said unsaved until saved, a target tested as
shown, no grooved frame, and the profiles applied again within a minute
while a node can't take one. janusd didn't change: this run checks the
Controller's changes on the lab and repeats the update steps.
The scenarios: [Lab test scenarios](lab-scenarios.md).

## Verdict

**Ready to promote.**

- **A node updated to this release gets the fleet's profile at once**: the
  auto-scaled machine, on v2026.10.15-2 and *unsupported*, updated through
  the Controller in 14 s - the profile applied **26 s** after it was
  ready (up to ten minutes before).
- **A target is tested as shown**: on the lab's Controller, a target never
  saved - Logstash over TLS with the bench's own CA - answered *sent*, and
  its record reached Elasticsearch; a saved target is tested as before, an
  unknown one without its configuration is a 404. The Controller serves
  the new pages (the targets folded, the unsaved bar) - walked in Chromium
  on the branch, both themes, no console error.
- Everything else matched v2026.10.16-2: the Controller's update, the
  rolling update, each boot's kernel messages from the updated nodes
  (707 a boot, under their names), HAProxy stopped and started, SELinux
  enforcing with no denial, CIS 33/33.
